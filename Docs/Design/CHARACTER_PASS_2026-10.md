# Персонаж: вид от первого лица, камера, анимации, движение — план прохода

Claude, 2026-10-07. Rio: «по персонажу надо пройтись, давно им не занимались, он просится: нормально от первого
лица, камеру улучшить, анимации и движение». Это план на после сборки exe; сейчас ничего не меняется. Всё, что
ниже про текущее состояние, проверено по коду 07.10 (`Source/APS_ALPHA/Pawns/Characters/*`) и аудиту 27.09.

## 1. Что есть сейчас

**Классы.** Производственный пилот — `BP_CustomGravityCharacter_SpeedModes` (RANGER, по умолчанию) →
`AAPSSpeedModeCharacter` → `ACustomGravityCharacter` → `ACharacter`. STANDARD — базовый класс. Рядом лежат
старые слои (`GravityCharacterPawn`, `SpaceCharacter`, `SurfaceCharacterPawn`, `APS_GravityCharacter`,
`GravityPawn`), в игре не используются; аудит 27.09 отмечал, что они сосуществуют.

**Камера.** Только третье лицо. `CameraBoom` 300 см с лагом (`CameraLagSpeed` 10, сабстеппинг 1/120), коллизия
штанги включена. Направление взгляда — собственное состояние персонажа: `CameraForwardOnGravityPlane` +
`CameraPitch` (−80…80°), `bUsePawnControlRotation = false` везде; `SynchronizeCharacterToCamera` каждый тик
поворачивает актора к камере, поэтому `SetControlRotation` ничего не делает — для телепортов есть
`SetViewDirection`. Верх камеры следует за гравитацией (`CameraAlignmentSpeed` 8), в невесомости — свой
кватернион вида. Режим стройки отводит камеру (1800 см, 55°). На борту корабля персонаж прикреплён к нему, лаг
отключается. У `AAPSSpeedModeCharacter` лаг растёт с темпом (`CameraLagShare` 0,75), чтобы камера не ломалась на
быстром беге.

**В корабле.** Пилот при посадке в кресло просто скрывается — анимации посадки нет (аудит 27.09). Камера полёта —
штанга корабля 1000 см, на скорости вытягивается (`BaseCameraArmLength × (1,3 + …)`), наклонена на −12°
(разбор 06.10: цель «уходит вниз», в плане ночи — маркер вектора полёта). Есть переключение штанги 1000 ↔ 35 см
(`Spaceship.cpp:6760/6774`) — зачаток вида «из кабины», но без кресла и без тела. Codex 07.10: камера внутри
кабин L17/S24 плохая (чёрная консоль в кадре, слишком близко к шлему).

**Анимации.** AstroGirl на скелете UE5-манекена (`SK_AstroGirl_Quinn`, 45k tris, 1 LOD). Два ABP, подгружаются по
пути в конструкторе: `APS_ABP_Manny` (поверхность) и `ABP_ZeroGAnim` (невесомость); переключение по гравитации
(`ApplyAnimationMode`). Около 6 наземных клипов и около 20 для невесомости; бленд-спейс ходьба/бег с ускорением
проигрывания до 2,2× (`AnimationRunSpeed` 500, `MaxAnimationPlayRate`), сглаженные скорость и направление. Нет:
старта/остановки/разворота на месте, поворотов, прыжка по фазам, посадки в кресло, подъёма по лестнице,
взаимодействий (рычаг, поднять/нести), IK ног. Часть анимаций и ABP лежат в игнорируемых git папках
(`Characters`, `AstroGirl`); ходячие клипы ссылаются на отсутствующий скелет `SK_Pirate` (только источник).

**Движение.** Гравитация через `SetGravityDirection` UE 5.4: радиальная (планета), направленная (станция, корабль),
невесомость с полётом (1200 см/с, спринт до 6000), переходы с блендом ориентации 0,8 с. Три темпа по клавишам
1/2/3 (Walk / Indoor / Open) с плавным поворотом к направлению движения, спринт с разгоном, буст-прыжок по
двойному нажатию (Open). Выход из техники: `SettleAfterVehicleExit`. Известные проблемы (06.10): «бег персонажем
подфризивает» (не разобрано), ходьба по летящему кораблю роняет fps (коллизия корпуса, лечится прокси), гравитация
на станции после выхода из корабля не проверена.

**Взаимодействие.** `TryInteract`: трасса от камеры на 600 см, подсказка-виджет; техника, корабль, терминалы.
В ORIGIN на это ляжет рычаг питания, алтарь, перенос детали привода (концепт §4).

## 2. Чего хотим

1. **Вид от первого лица с телом** (как в Star Citizen): камера на кости головы, своё тело и ноги видны, руки на
   консолях и рычагах; переключение V; в кабине корабля — настоящий вид из кресла с интерьером. Это и ответ на
   плохие кабинные камеры: кресло задаёт точку глаз.
2. **Камера третьего лица лучше:** плечевое смещение, чище переходы гравитации, без рывков при стыковке/выходе,
   штанга корабля без наклона −12° (или с маркером вектора).
3. **Полный набор анимаций:** старт/стоп/разворот, повороты на месте, прыжок по фазам, посадка/вставание с кресла,
   взаимодействия (рычаг, нажать, поднять/нести), IK ног на рельефе WorldScape (поверхности неровные — без IK ноги
   висят), позже — лестница и перелезание.
4. **Движение по ощущению:** разгон/торможение по кривым, скорость по уклону, высота шага, посадка после прыжка,
   контроль в воздухе по темпу; без фризов на беге.
5. Всё под выключателями и с перф-A/B (кадры ходьбы q06/q07/q09 из базы 06.10), старое поведение остаётся.

## 3. Как делать — предложение

### 3.1 Анимации: Game Animation Sample от Epic

Главная находка: AstroGirl стоит на **том же скелете UE5-манекена**, что и бесплатный Game Animation Sample
Epic для UE 5.4 (500+ анимаций: idle, старт/стоп, пивоты, повороты на месте, бег, прыжки по фазам, traversal —
перелезание/запрыгивание, посадка на объекты). Ретаргет не нужен — те же кости. Это закрывает п. 3 почти целиком
и бесплатно (контент Epic, только для UE).

Чего **не** брать оттуда сразу: Motion Matching (Pose Search). В 5.4 он экспериментальный и считает траекторию в
мировом Z-up; наш персонаж живёт в произвольной гравитации. Сначала классический ABP на той же библиотеке:
состояния idle / start / loop / stop / pivot / turn-in-place, прыжок start-apex-land, aim offset для первого
лица, слой верхней половины для взаимодействий. Motion Matching — отдельный спайк потом, если захочется.

### 3.2 Первое лицо с телом

- Второй камерный компонент на сокете головы меша (`FirstPersonCamera`), голова скрывается (масштаб кости или
  материал-маска), FOV 90–100, небольшой наклон тела в сторону взгляда через aim offset.
- Направление взгляда берётся из уже существующего состояния (`CameraForwardOnGravityPlane`, `CameraPitch`):
  `SynchronizeCharacterToCamera` и так поворачивает тело за камерой, в первом лице это именно то, что нужно.
  Гравитация, невесомость, прикрепление к летящему кораблю — всё уже работает на уровне актора.
- Переключение V (и CVar `aps.Char.FirstPerson`), режим стройки принудительно в третьем лице, HUD-подсказки
  взаимодействия — те же.
- В кресле: камера от сокета кресла (`SOCK_Pilot` на каждом корабле, задаёт точку глаз и направление; это
  чинит кабины L17/S24 по месту), тело пилота видно и сидит; снаружи — прежняя штанга.

### 3.3 Кресло и взаимодействия

- Посадка/вставание — монтажи из библиотеки Epic (sit/stand) с привязкой к `SOCK_Pilot`; пилот больше не
  скрывается. Переход камеры 3P → кабина за 0,4 с.
- Взаимодействия: рычаг (reach + push), нажатие, поднять/нести (деталь привода на сокете руки), положить. Простые
  монтажи верхней половины + IK руки к точке (Control Rig), чтобы рука реально ложилась на рычаг P-01 из брифов.

### 3.4 IK ног и движение

- Control Rig с размещением стоп (встроенный в UE5 foot placement) — ноги на уклонах WorldScape, наклон таза.
- Кривые разгона/торможения по темпам, скорость по уклону, высота шага 40 см, посадка после прыжка с коротким
  присядом (Open), контроль в воздухе по `AirControl` темпа.
- Разобрать «бег подфризивает»: профиль Insights на беге по поверхности (подозрение на обновление лага камеры
  сабстепами 1/120 + трассы `TryInteract` каждый тик + WorldScape-патчи).

### 3.5 Арт персонажа (позже, отдельно)

AstroGirl остаётся. Нужны LOD (45k tris, 1 LOD), проверка скафандра крупным планом (Rio смотрит 0,5–1 м). Идея
на потом: забрало шлема закрывается при выходе из пригодной атмосферы (пригодность миров уже считается) — дешёвая
и заметная деталь первого лица.

## 5. Риски

- Произвольная гравитация ломает всё, что в движке считает Z-up: Motion Matching, часть traversal из библиотеки
  Epic (перелезание считает высоту по Z) — брать клипы, не логику.
- Скрытие головы в первом лице даёт артефакты тени и отражений — проверять в кабине и на станции.
- Кабины кораблей делались без точки глаз: без `SOCK_Pilot` на каждом корабле первое лицо в кресле не работает;
  это 25 записей каталога, часть кабин (L17, S24) придётся подвинуть.
- Анимации сейчас в игнорируемых папках: перенос нужен до exe на другой машине, иначе персонаж без ABP.
- Ходьба по летящему кораблю — отдельная история коллизий (прокси), не смешивать с этим проходом.
